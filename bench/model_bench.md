# 本地模型實測題組

本地模型實測（`stages/trial/model.py`，說明 `docs/stages/trial_model.md`）讀這份：每個本地模型都跑同一套題目，不同模型的結果才能放在一起比。

## 怎麼改

- 改了題目、答案、功能清單或速度題，**題組版本要加一**：只有同一版題組的結果會放進「同一台測過的其他模型」對照。
- 數學題的「答案」欄程式拿來對答案：寫數字、分數（`2/3`）或小數；模型答 0.667、66.7% 也算對（差距在 0.5% 內）。
- 功能清單是俄羅斯方塊的需求，也是逐條核對的準則（Cursor agent 在瀏覽器裡實際操作，跟效果實驗同一套）。
- 速度題用固定長度產生（不看模型什麼時候想停），「輸入」寫 `長文` 的那題由程式把固定段落重複到 `[local_model] long_tokens` 個 token 左右；其他題的「名稱」就是輸出種類（文章裡依輸出種類比速度）。
- context 掃描用同一段長文段落組成 `[local_model] ctx_scan` 列的長度，每次前面加隨機鹽（避免 llama.cpp 的 prefix cache 讓數字失真）。
- 數學題另跑一次「給 Python 工具」：模型可以呼叫 run_python（沒有網路的容器，每次 30 秒），對答案的方式一樣。

## 長文段落

速度題 s3 用這段重複組成長輸入，最後接一句「請用五點條列整理上面這份文件的重點。」

| 段落 |
| --- |
| 本地推論是指把語言模型放在自己的電腦或伺服器上執行，不把資料送到雲端。影響速度的因素有幾個：模型的參數量、每個 token 實際會啟動的參數量、量化後每個權重佔幾個位元、顯示卡記憶體夠不夠把整個模型放進去、放不下時有多少層或多少專家要放到系統記憶體由 CPU 計算，以及推論引擎有沒有針對這個架構做最佳化。處理輸入的速度通常比產生輸出快很多，因為輸入可以一次平行計算，輸出只能一個 token 一個 token 產生。投機解碼用一個小的草稿模型先猜幾個 token，再讓大模型一次驗證，猜中越多越快，猜錯就白花草稿的計算。 |
